This repository is an auditable refinement scaffold for the ActiveTrust paper. It separates three classes of evidence: the paper’s **reported aggregate values**, the author-supplied **raw experiment archive**, and **derived outputs generated by code**. It deliberately does not synthesize missing experiment observations.

## Why this refinement is needed

The public repository history currently contains documentation and metadata but no ActiveTrust implementation, NS-3 project, raw runs, tests, or figure-generation source. The original README also describes a different composite direct/indirect trust formula and different baseline/result names. This refined pack corrects the repository structure and provides a strict validation/analysis layer that can be connected to the authors’ real NS-3 experiment archive.

## Repository structure

```text
src/activetrust_analysis/   Validation, statistics, and plotting modules
scripts/run_pipeline.py     CLI for validate/summarize/plot
configs/                    Experiment configuration templates
data/raw/                   Author-supplied raw run archive; currently schema only
data/reported/              Values transcribed from the supplied paper; not regenerated
results/                    Machine-generated validation and summary outputs
figures/                    Figures generated from raw data only
artifacts/source_figures/   Source-derived figures extracted from the supplied PDF
artifacts/                  Provenance and submission support files
docs/                       Reproducibility and IEEE artifact documentation
tests/                      Unit tests
.github/workflows/          Continuous-integration workflow
```

## Installation

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip install -e .
```

## Validation

Place the real per-run archive at `data/raw/raw_runs.csv` using the supplied schema. Then run:

```bash
python scripts/run_pipeline.py validate \
  --input data/raw/raw_runs.csv \
  --report results/validation_report.json
```

A zero-row schema file is treated as **pending**, not as a valid experiment. The command exits successfully only when no error-level schema or range violations are found.

## Reproducible summaries and figures

After the raw archive is present and passes validation:

```bash
python scripts/run_pipeline.py summarize \
  --input data/raw/raw_runs.csv \
  --output results/raw_run_summary.csv

python scripts/run_pipeline.py plot \
  --input data/raw/raw_runs.csv \
  --output-dir figures
```

The pipeline computes means and 95% confidence intervals from the actual run-level values. It does not use the reported PDF aggregate table as if it were raw data.

## Evidence policy

The file `data/reported/reported_results_summary.csv` is retained for traceability only. Every row is marked `reported_not_regenerated`. It must not be used as evidence that the GitHub repository reproduces the paper. The authors must add the real simulator, configuration files, seed manifest, raw output, and analysis scripts before claiming reproducibility.

## IEEE submission use

The `docs/` directory contains the repository audit, reproducibility manifest, and submission guidance. The package is designed to support IEEE Traditional submission routes, but the manuscript must be updated with the actual artifact URL and raw-data availability statement before submission.
